# 授权 Web/API 安全测试

## 启动检查

开始前确认以下条件，缺少任一项就停止：

- 已取得书面授权，授权人、依据和截止时间明确。
- 目标基址和域名范围清楚，所有请求都经过范围校验。
- 测试身份与角色明确，密码只由运行时提供。
- 成功标准是证明可复核的业务影响，扫描完成不构成成功。

## 硬性边界

- 只做授权 Web/API 测试。
- 禁止删除数据、批量写入、密码猜测、DoS、提权、横向移动、反向 Shell、EDR 规避、无线网络测试、AD 测试和二进制利用。
- 写入仅限授权明确的单条可逆验证；不得修改他人账户、权限、密码或业务状态。
- 目标范围外的主机、接口和跳转只记录线索，不继续探测。
- 不得编造请求、截图、影响或复现步骤。

## 执行流程

1. 使用 `security_browser` 的 `open` 打开目标，随后立即执行 `snapshot`，记录页面结构和可用引用。
2. 页面加载或交互后执行 `security_browser` 的 `network_requests`，检查接口路径、状态码、资源类型和请求关系，识别隐藏接口与异常响应。
3. 根据页面、响应状态、对象标识、权限差异和业务状态选择测试信号，优先验证未授权访问、对象越权和身份边界。
4. 使用 `security_http_request` 获取可复核的请求与响应证据。每次请求保持在范围内，并避免读取与目标无关的数据。
5. 对每个候选问题复现最小攻击链。只有请求、响应、影响和修复建议能够相互印证时，才记录为发现。
6. 使用 `security_browser` 的 `screenshot` 保存关键页面证据。截图文件名应能对应测试步骤。
7. 使用 `security_record_finding` 记录标题、严重程度、置信度、证据、影响和修复建议。
8. 使用 `security_finish` 保存摘要、风险评分和 Markdown 报告。每次执行只调用一次。

## 证据标准

- 每条发现包含目标 URL、测试身份、请求方法、关键响应差异和可复核步骤。
- 登录状态下的发现必须注明会话身份，禁止表述为匿名未授权。
- 截图只用于支持文字证据，结论仍以请求和响应为准。
- 风险评分体现现实影响和数据范围，扫描数量不参与评分。

## 完成条件

- 至少保存一条成功的 HTTP 或浏览器网络请求和一张页面截图。
- 授权范围内的高价值信号已经覆盖。
- 每个发现具备可复核证据和明确影响。
- 未确认的问题不写入发现列表。
- 优先调用 `security_finish` 保存结果。无法调用时，输出完整的 Markdown 文字报告，Runtime 会保存已获得的证据并生成最终报告。
